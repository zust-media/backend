# 04 - 用户管理接口

## 接口列表

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| GET | `/api/users/list` | 管理员 | 用户列表 |
| POST | `/api/users/create` | 管理员 | 创建用户 |
| PUT | `/api/users/:id` | 管理员 | 更新用户信息 |
| DELETE | `/api/users/:id` | 管理员 | 删除用户及其图片 |
| GET | `/api/users/:identifier` | 不需要 | 用户详情及上传图片 |

---

## 用户对象结构

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | integer | 用户ID |
| `username` | string | 用户名 |
| `nickname` | string | 昵称 |
| `role` | string | 角色：`admin` / `user` |
| `uuid` | string | 用户UUID |
| `slug` | string | 个性地址 |
| `bio` | string | 个人简介 |
| `created_at` | string | 注册时间 |

---

## GET /api/users/list - 用户列表

**认证要求**：管理员（`requireAdmin`）

### 请求参数

无

### 返回值

**成功 200：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `users` | array | 用户列表（含每个用户的图片上传数量） |

```json
{
  "users": [
    {
      "id": 1,
      "username": "admin",
      "nickname": "管理员",
      "role": "admin",
      "uuid": "550e8400-...",
      "slug": "admin",
      "bio": "超级管理员",
      "created_at": "2025-01-01T00:00:00.000Z",
      "image_count": 350
    }
  ]
}
```

**失败 401 / 403**：非管理员。

### 业务处理流程

```
1. requireAdmin：验证管理员权限
2. SELECT u.*, COUNT(i.id) FROM users u LEFT JOIN images i
   GROUP BY u.id ORDER BY u.id ASC
3. 返回 200
```

## POST /api/users/create - 创建用户

**认证要求**：管理员（`requireAdmin`）

### 请求参数

| 参数名 | 位置 | 类型 | 必需 | 默认值 | 说明 |
|--------|------|------|------|--------|------|
| `username` | Body | string | 是 | — | 用户名，至少3字符，仅字母数字下划线 |
| `password` | Body | string | 是 | — | 密码，至少6个字符 |
| `nickname` | Body | string | 否 | `""` | 昵称 |
| `role` | Body | string | 否 | `"user"` | 角色：`admin` / `user` |
| `slug` | Body | string | 否 | — | 个性地址 |

### 请求示例

```json
{
  "username": "neweditor",
  "password": "pass123456",
  "nickname": "编辑小王",
  "role": "user",
  "slug": "editor-wang"
}
```

### 返回值

**成功 201：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `message` | string | `"用户已创建"` |
| `user` | object | 新创建的用户信息 |

**失败响应：**

| 状态码 | 错误信息 | 触发条件 |
|--------|----------|----------|
| 400 | `"用户名不能为空"` | username 为空 |
| 400 | `"用户名至少3个字符"` | username < 3字符 |
| 400 | `"用户名只能包含字母、数字和下划线"` | username 含非法字符 |
| 400 | `"密码至少6个字符"` | password < 6字符 |
| 400 | `"用户名已存在"` | username 已注册 |
| 401 | `"未登录"` | Token未提供 |
| 403 | `"需要管理员权限"` | 非管理员 |

### 业务处理流程

```
1. requireAdmin：验证管理员权限
2. 提取参数并校验格式
3. 检查用户名唯一性
   ↓ 重复 → 400 用户名已存在
4. bcrypt 哈希密码（salt rounds=10）
5. 生成 UUID
6. 处理 slug（可选）
7. INSERT INTO users
8. 返回 201 新用户信息
```

## PUT /api/users/:id - 更新用户

**认证要求**：管理员（`requireAdmin`）

### 请求参数

| 参数名 | 位置 | 类型 | 必需 | 说明 |
|--------|------|------|------|------|
| `id` | Path | integer | 是 | 用户ID |
| `username` | Body | string | 否 | 新用户名 |
| `password` | Body | string | 否 | 新密码（≥6字符） |
| `nickname` | Body | string | 否 | 新昵称 |
| `slug` | Body | string | 否 | 新个性地址 |
| `role` | Body | string | 否 | 新角色：`admin` / `user` |

### 请求示例

```json
{
  "nickname": "编辑老李",
  "role": "admin"
}
```

### 返回值

**成功 200：**

```json
{
  "message": "用户已更新",
  "user": { ... }
}
```

**失败响应：**

| 状态码 | 错误信息 | 触发条件 |
|--------|----------|----------|
| 400 | `"无效的用户ID"` | id 非数字 |
| 400 | `"用户名不能为空"` | 提供的 username 为空 |
| 400 | `"用户名已存在"` | username 被他人占用 |
| 400 | `"没有需要更新的字段"` | 请求体无有效字段 |
| 401 / 403 | 同上 | — |
| 404 | `"用户不存在"` | 目标用户不存在 |

### 业务处理流程

```
1. requireAdmin：验证管理员权限
2. 校验用户ID + 查询用户
   ↓ 不存在 → 404
3. 构建动态 UPDATE 语句（仅更新提供的字段）
   - username → 校验格式+唯一性
   - password → bcrypt 新哈希
   - nickname → 直接更新
   - slug → 直接更新
   - role → 验证值是否合法
4. 执行 UPDATE
5. 查询最新用户信息
6. 返回 200
```

## DELETE /api/users/:id - 删除用户

**认证要求**：管理员（`requireAdmin`）

### 请求参数

| 参数名 | 位置 | 类型 | 必需 | 说明 |
|--------|------|------|------|------|
| `id` | Path | integer | 是 | 用户ID |

### 返回值

**成功 200：**

```json
{
  "message": "用户已删除"
}
```

**失败响应：**

| 状态码 | 错误信息 | 触发条件 |
|--------|----------|----------|
| 400 | `"不能删除管理员账户"` | 目标用户是 admin |
| 400 | `"无效的用户ID"` | id 无效 |
| 401 / 403 | 同上 | — |
| 404 | `"用户不存在"` | — |

### 业务处理流程

```
1. requireAdmin：验证管理员权限
2. 查询用户
   ↓ 不存在 → 404
3. 检查是否管理员
   ↓ 是 → 400 不能删除管理员账户
4. 查询该用户所有图片的 filename
5. 遍历删除磁盘上的物理图片文件
6. 删除 image_tags 中该用户图片的关联
7. 删除 images 表中该用户的记录
8. 删除 users 表中该用户记录
9. 返回 200
```

## GET /api/users/:identifier - 用户详情及图片

**认证要求**：不需要（公开接口）

### 请求参数

| 参数名 | 位置 | 类型 | 必需 | 默认值 | 说明 |
|--------|------|------|------|--------|------|
| `identifier` | Path | string | 是 | — | 用户UUID 或 slug |
| `page` | Query | integer | 否 | `1` | 页码 |
| `limit` | Query | integer | 否 | `20` | 每页数量（最大 50） |

### 返回值

**成功 200：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `user` | object | 用户信息对象 |
| `images` | array | 该用户上传的图片列表 |
| `pagination` | object | 分页信息 |

```json
{
  "user": {
    "id": 2,
    "username": "user123",
    "nickname": "普通用户",
    "role": "user",
    "uuid": "660e8400-...",
    "slug": "user-123",
    "bio": "摄影爱好者",
    "created_at": "2025-06-15T00:00:00.000Z"
  },
  "images": [
    { "id": 100, "title": "城市夜景", ... }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 45,
    "total_pages": 3
  }
}
```

**失败 400：**

```json
{
  "error": "无效的用户标识"
}
```

**失败 404：**

```json
{
  "error": "用户不存在"
}
```

### 业务处理流程

```
1. 校验 identifier 非空
2. 查询用户：WHERE uuid = ? OR slug = ?
   ↓ 不存在 → 404
3. 分页查询该用户的图片（ORDER BY created_at DESC）
4. 格式化图片（标签、EXIF、签名URL）
5. 返回 200
```

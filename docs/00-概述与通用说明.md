# ZustMedia API 文档 - 概述与通用说明

## 1. 基础信息

| 项目 | 值 |
|------|---|
| 基础URL | `http://localhost:8080` |
| 协议 | HTTP |
| 数据格式 | JSON（上传接口使用 multipart/form-data） |
| 字符编码 | UTF-8 |

## 2. 默认账号

| 角色 | 用户名 | 密码 |
|------|--------|------|
| 管理员 | `admin` | `admin123` |
| 普通用户 | `user` | `user123` |

## 3. 认证机制

### 3.1 JWT Token 认证

系统使用 JWT（JSON Web Token）进行身份认证。除公开接口外，所有管理类接口需要携带 Token。

- **Token 获取**：通过 `POST /api/auth/login` 登录接口获取
- **Token 携带方式**：在请求头中添加 `Authorization: Bearer <token>`
- **Token 有效期**：登录成功后返回的 token 用于后续请求

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

### 3.2 认证中间件（`authenticate`）

- **作用**：解析请求头中的 Token，将用户信息挂载到 `req.user`
- **注册方式**：作为全局中间件注册在 `app.use(authenticate)`
- **行为**：Token 有效则 `req.user` 包含 `{ id, username, role }`；Token 无效或未提供则 `req.user = null`
- **不影响路由**：该中间件不会拦截请求，仅做解析。具体权限校验由 `requireAuth` / `requireAdmin` 负责

### 3.3 `requireAuth` 中间件

- **作用**：要求用户必须已登录
- **失败返回**：`401 { "error": "未登录" }`
- **成功**：放行请求，`req.user` 已包含用户信息

### 3.4 `requireAdmin` 中间件

- **作用**：要求用户必须是管理员角色
- **内部**：先调用 `requireAuth`，再检查 `req.user.role === 'admin'`
- **失败返回**：`401 { "error": "未登录" }` 或 `403 { "error": "需要管理员权限" }`

## 4. 图片访问签名机制

为防止图片链接被滥用，图片访问使用 HMAC-SHA256 签名验证。

### 4.1 签名算法

```
签名内容 = filename + 所有query参数（按key排序，不含sig）
签名 = HMAC-SHA256(签名内容, SECRET_KEY).hex()
```

### 4.2 签名参数

| 参数 | 必需 | 说明 |
|------|------|------|
| `sig` | 是 | HMAC-SHA256 签名值 |
| `exp` | 否 | 过期时间戳（Unix 秒），过期后链接失效 |

### 4.3 `requireValidSig` 中间件

- **作用**：校验图片请求的 URL 签名
- **失败返回**：`403 { "error": "签名无效或已过期" }`

### 4.4 `generateSignedUrl` 工具函数

- **用途**：生成带签名的图片访问 URL
- **返回**：完整的签名 URL 字符串
- **使用场景**：所有返回给前端的 `thumbnail_url`、`preview_url`、`download_url` 均通过此函数生成

## 5. 图片处理机制

### 5.1 缩略图生成（`generateThumbnail`）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `filename` | string | — | 存储文件名 |
| `width` | number | 300 | 缩略图宽度 |
| `height` | number | — | 缩略图高度（可选） |
| `quality` | number | 80 | JPEG 质量 (1-100) |
| `noWatermark` | boolean | false | 是否跳过水印 |

处理流程：
1. 读取 uploads 目录下的原图
2. 若为 SVG 格式，直接返回不做处理
3. 若原图宽度 > 目标宽度，等比缩放至目标宽度
4. 转为 JPEG 格式
5. 如需要，叠加水印

### 5.2 图片服务（`serveImage`）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `filename` | string | — | 存储文件名 |
| `w` | number | 0 | 请求宽度（像素），为0或未提供则不缩放 |
| `q` | number | 80 | JPEG/PNG 质量 |
| `m` | string | null | 水印文件路径（相对于 public/） |

处理流程：
1. 读取原图
2. 若指定了宽度 `w` 且原图更宽，等比缩放
3. 按格式编码（PNG 保持 PNG，其他转 JPEG）
4. 若设置了 `forceWatermark=true` 或有水印参数，叠加水印

### 5.3 水印机制

水印配置文件位于 `public/` 目录，由 `config/app.js` 中的 `watermark` 配置控制。

| 配置项 | 说明 |
|--------|------|
| `sizeRatio` | 水印大小占图片最长边的比例 |
| `opacity` | 水印不透明度 (0-1) |
| `position` | 水印位置（center/left/right/top/bottom 组合） |
| `marginX` / `marginY` | 水印边距（占图片尺寸的比例） |
| `forceWatermark` | 是否强制所有图片加水印 |

## 6. 通用错误码

| HTTP 状态码 | 含义 | 常见场景 |
|------------|------|----------|
| 200 | 成功 | 正常响应 |
| 201 | 创建成功 | 资源创建（注册、上传等） |
| 400 | 请求参数错误 | 缺少必填参数、参数格式错误、值超出范围 |
| 401 | 未认证 | 未登录或 Token 无效/过期 |
| 403 | 无权限 | 非管理员执行管理操作、签名无效 |
| 404 | 资源不存在 | 图片/用户/标签/分类未找到 |
| 413 | 请求体过大 | 文件超过最大上传限制 |
| 500 | 服务器内部错误 | 未预期的异常 |

错误响应格式：
```json
{
  "error": "错误描述信息"
}
```

## 7. CORS 配置

- 允许任意来源 (`origin: *`)
- 允许的方法：`GET`, `POST`, `PUT`, `DELETE`, `OPTIONS`
- 允许的请求头：`Content-Type`, `Authorization`
- 预检请求缓存时间：86400 秒（24小时）

## 8. 分页规范

需要分页的接口使用统一的参数和响应格式：

**请求参数：**

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `page` | integer | 1 | 页码（从1开始） |
| `limit` | integer | 20 | 每页条数（最大 50） |

**响应分页信息：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `page` | integer | 当前页码 |
| `limit` | integer | 每页条数 |
| `total` | integer | 总记录数 |
| `total_pages` | integer | 总页数 |

## 9. 文件上传限制

通过 `config/app.js` 中的 `image` 配置控制：

| 配置项 | 说明 |
|--------|------|
| `maxFileSizeMB` | 单文件最大上传大小（MB） |
| `maxBatchCount` | 单次批量上传最大文件数 |
| `allowedTypes` | 允许的 MIME 类型列表 |

## 10. 敏感词过滤

系统内置敏感词/屏蔽词过滤（`blocked-keywords.js`），用于检测上传标题、描述等内容是否包含不当词汇。触发时返回 400 错误。
